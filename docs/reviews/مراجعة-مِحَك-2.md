### 2.4 معالجة الأخطاء والحالات الحدّية — **5.5/10**

هذا أضعف بند، وفيه أخطر ملاحظة في التقرير.

**🔴 الجداول داخل المواد تُحذف بصمت من مصدر qanoonsa.** في `adapters/qanoonsa.py`، دالة `QanoonsaAdapter.parse`:

```python
for el in content.find_all(["h2", "h3", "h4", "p", "li", "blockquote"]):
    if el.find_parent(["li", "blockquote"]) is not None:
        continue
```

`table` ليس في القائمة. لما تكون الصفحة مقسّمة لمواد، أي جدول داخل مادة يضيع: الخلايا المكتوبة نصًا مباشرًا تختفي كلها، والخلايا اللي فيها `<p>` تتسطّح إلى فقرات بلا بنية. `htmlmd.table_to_markdown` موجودة، لكنها تُستدعى فقط في مسار المتن النثري. أعدت إنتاج المشكلة كالتالي:

```
المدخل:  <h2>المادة الأولى</h2><p>…وفق الجدول الآتي:</p>
         <table><tr><th>المخالفة</th><th>الغرامة</th></tr>
                <tr><td>مخالفة أ</td><td>1000 ريال</td></tr>
                <tr><td><p>مخالفة ب</p></td><td><p>5000 ريال</p></td></tr></table>
المخرج:  'تكون الغرامات وفق الجدول الآتي:\n\nمخالفة ب\n\n5000 ريال'
```

وضاع صف الترويسة وصف «مخالفة أ» كاملين. **وهذا حاصل فعلًا في المُدوَّنة الملتزمة.** من 430 وثيقة qanoonsa مقسّمة لمواد، **ولا وحدة** فيها جدول Markdown، و7 منها تقول «الجدول الآتي/التالي» ثم تنتقل مباشرة للفقرة التالية. مثال من `laws/لائحة/اللائحة التنفيذية لتنظيم الدعم السكني.md`:

```
يمنح المتقدم نقاطا بناء على عدد أفراد أسرته بحد أقصى عشرون نقطة وفق الجدول الآتي:

وللوزارة تعديل النقاط المنصوص عليها في هذا الجدول في حال التزاحم…
```

جدول النقاط، وهو جوهر المادة، مفقود. في مُدوَّنة قانونية، **مادة مبتورة بلا إشارة أسوأ من مادة غائبة**، لأن القارئ ما عنده أي سبب يشك فيها. ولا `validate_document` ولا `lint_corpus` ولا `smoke` يلتقطها.

**الحل:**
1. أضف `"table"` إلى `find_all` في `QanoonsaAdapter.parse`، وأضف `"table"` إلى `find_parent` حتى لا تتكرر الـ `p` الداخلية.
2. أضف `_ArticleCollector.feed_table(md)` تُلحق `htmlmd.table_to_markdown(el)` بنص المادة الجارية.
3. أضف fixture فيها جدول داخل مادة.
4. أضف حارسًا في `schema.validate_document` و`lint_corpus` يرصد «الجدول الآتي:» أو «وفق الجدول» غير متبوعة بسطر يبدأ بـ `|`.
5. أعد سحب الوثائق السبع على الأقل.

**🟠 سقف حجم الاستجابة لا يحمي الذاكرة.** في `fetch.py`، دالة `Fetcher._check_size`:

```python
if len(response.content) > MAX_RESPONSE_BYTES:
```

الطلب في `_get_once` يُرسل بلا `stream=True`، يعني `requests` ينزّل الجسم كاملًا قبل هذا السطر. التعليق يقول إنه «يُرفض قبل تحميله كاملًا»، والواقع عكس ذلك. الفحص الوحيد الفعّال هو `Content-Length`، وخادم يرسل chunked بلا طول يتجاوزه تمامًا. **الحل:** `session.get(..., stream=True)`، ثم قراءة `iter_content(65536)` مع عدّاد يرفع `FetchError` عند تجاوز السقف، ثم `response._content = b"".join(chunks)`.

**🟡 nezams يُسقط مادة كاملة بصمت.** في `adapters/nezams.py`، دالة `NezamsAdapter.parse`:

```python
if heading is None or content is None:
    continue
```

إذا تغيّر قالب مادة واحدة، تختفي من الناتج ويستمر التسلسل بفجوة، وتنزل ضمن الـ 323 تحذير تسلسل المختلطة. **الحل:** اجمع عدد العناصر المُسقطة وضعه في حقل تحذير يقرأه `validate_document`، مثل «أُسقط N عنصر li.subject بلا عنوان/متن».

**🟡 `audit_duplicates` يكتب كتابة غير ذرّية، ويترك روابط يتيمة.** في `audit_duplicates.annotate_duplicates` السطر `path.write_text(new_text, ...)`، بينما بقية سكربتات الصيانة تستخدم `atomic_write`. والدالة تعالج فقط المجموعات اللي فيها أكثر من ملف، فإذا حُذفت نسخة، يبقى `also_available_from` في النسخة الباقية يشير لرابط ما عاد له ملف. **الحل:** استبدل `write_text` بـ `atomic_write`، وفي نفس المرور احذف الحقل من أي ملف عنوانه ما عاد مزدوجًا.

**🟡 `read_field` لا يفك التهريب.** في `frontmatter.read_field`، الحقل `title: "قرار \"أ\""` يرجع `قرار \"أ\"` بالشرطة العكسية. `audit_duplicates` يستدعي `unquote` بعده، لكن `build_index` و`lint_corpus` لا يستدعونه. المُدوَّنة الحالية ما فيها عنوان بعلامة تنصيص، فالخطأ كامن، لكن أول عنوان من هذا النوع بيطلع مشوّهًا في `index.json`. **الحل:** خلّ `read_field` نفسها تُرجع `unquote(...)` للقيم المقتبسة، واحذف الاستدعاءات اليدوية.

**🟡 تطبيع الحالة يطابق خطأ داخل الكلمات.** في `status._RULES` النمط `[أإا]لغ` بلا حد كلمة يطابق «الغ» داخل «البالغ» و«المبالغ». جرّبته وطلع:

```
normalize_status("ساري - البالغ عدده") → ('ملغى', …)
```

ما في وثيقة حالية تأثرت، لكن هذا بالضبط نوع الخطأ اللي يعكس جواب «هل النظام نافذ؟». **الحل:** `(?<!\w)[أإا]لغ` ومعه اختبار لـ «البالغ».

**🟠 حقن أوامر عبر مُدخل `workflow_dispatch`.** في `.github/workflows/update-corpus.yml`، خطوة «تحديد شريحة هذا الأسبوع»:

```yaml
if [ -n "${{ github.event.inputs.shard }}" ]; then
  echo "value=${{ github.event.inputs.shard }}" >> "$GITHUB_OUTPUT"
```

وبعدها `--shard "${{ steps.shard.outputs.value }}"`. التعبير يُستبدل نصيًا في السكربت قبل ما تشغّله bash، فمُدخل مثل `0/4"; curl … #` يتنفّذ بصلاحيات `contents: write` و`pull-requests: write`. الخطورة **متوسطة** وليست حرجة، لأن تشغيل `workflow_dispatch` يحتاج صلاحية كتابة على المستودع أصلًا. لكنه نمط تحذّر منه GitHub صراحة، وإصلاحه سطران. **الحل:**

```yaml
env:
  SHARD_INPUT: ${{ github.event.inputs.shard }}
run: |
  if [[ "$SHARD_INPUT" =~ ^[0-9]+/[0-9]+$ ]]; then echo "value=$SHARD_INPUT" >> "$GITHUB_OUTPUT"
  elif [ -n "$SHARD_INPUT" ]; then echo "صيغة شريحة غير صالحة" >&2; exit 1
  else echo "value=$(( $(date -u +%-V) % 4 ))/4" >> "$GITHUB_OUTPUT"; fi
```

وفي خطوة الجلب استخدم `--shard "$SHARD"` مع `env: SHARD: ${{ steps.shard.outputs.value }}`.

**🟡 جلب robots.txt يتبع التحويلات بلا فحص مضيف.** في `fetch.py`، دالة `Fetcher._robots_for`:

```python
resp = self.session.get(robots_url, timeout=self.timeout)
```

بقية الطلبات تتبع التحويلات يدويًا وتفحص مضيف كل وجهة (`_get_once`)، لكن هذا الطلب يستخدم `allow_redirects` الافتراضي (`True`). إذا تعرّض المصدر للاختراق، يقدر يحوّل طلب robots.txt إلى عنوان داخلي، وهذي بالضبط الحالة اللي صُمّم `host_allowed` لمنعها. **الحل:** مرّر الطلب عبر `self._get_once(robots_url, None, frozenset())` بدل `session.get` المباشر.

**🟡 لا ملف قفل للاعتماديات.** `pyproject.toml` يحدد حدودًا دنيا فقط (`requests>=2.31`)، فكل تشغيلة CI أو تحديث تثبّت آخر إصدار. هذا مقبول لأداة بهذا الحجم ومع Dependabot. **الحل الاختياري:** `pip-compile` إلى `requirements.lock` تستخدمه الـ workflows.

**متوسط القسم: 8/10.** سجل الأمن نظيف في الأساسيات (أسرار، صلاحيات، تثبيت Actions، قائمة مضيفات بيضاء، فحص كل تحويل)، والملاحظات كلها في الحواف.
